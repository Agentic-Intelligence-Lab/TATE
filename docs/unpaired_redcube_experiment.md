# 无配对重设计与验证：20 条真机 → 100 条 ego

日期：2026-10-11。服务器端口：1020。本实验按上下文中的“20 条真机 + 100 条 ego”执行。跨域配对关系只能用于最后评测，不能用于训练、选择参考轨迹、参数选择或建立训练伪标签。

上一版 `paired_redcube_experiment.md` 的训练和 CV 使用了跨域配对，不满足这个要求；其中的结果只能作为有配对参考，不能作为本任务的解答。这里重新准备训练输入、训练、封存预测，然后独立评测。没有 policy learning，也没有向机器人发送动作。

## 这次到底知道什么

训练端只接收六个数组：

- 100 条 ego：各自的 EEF 位置、姿态、初始场景特征。
- 20 条真机：各自的 TCP 位置、姿态、初始场景特征。

两批数量不同，顺序分别打乱。输入中没有 pair ID、episode ID、跨域对应表，也没有其余 80 条真机的轨迹。真机的“本条视频与本条 FK”是同一条演示内部的同步观测，不是“某条真机与某条 ego”的配对监督。

每条演示独立从夹爪开合中提取阶段，归一到 81 点；不通过与另一条演示比较来调整事件。场景特征取该条演示初始图像中“红方块中心减蓝盘中心”的二维坐标。**这依赖当前数据中共同的相机视角及一致的物体检测语义**，不是只凭“任务名称相同”就能成立。换相机时必须另行建立共同场景坐标。

如果完全没有共同场景信息，又不知道配对，只匹配两个轨迹分布并不能唯一确定某条 ego 应该如何校正；交换不同物体位置的对应关系也可能得到相同分布。因此这里明确使用每条演示自身可观测的物体位置作为连接两域的依据。

## 方法：场景条件均值 + 无配对残差传输

把一条动作拆成“这个物体位置下一般怎么运动”和“这条动作与一般动作的差别”。

1. 在 100 条 ego 内部拟合 `μ_E(c, s)`：场景位置 `c`、动作阶段 `s` 对应的平均 ego 轨迹。
2. 在 20 条真机内部独立拟合 `μ_R(c, s)`：同样的场景特征对应的平均真机轨迹。两次回归从不建立 ego→真机训练样本对。
3. 分别计算两批数据相对于各自条件均值的残差。用整个 81 点轨迹的共同低维空间描述变化，例如某条动作整体抬得更高、接近路线更弯，而不是独立随机移动每个点。
4. 仅从两域各自的残差协方差构建高斯传输矩阵，使 ego 残差的尺度和变化方向接近真机；没有计算逐条跨域残差或配对交叉协方差。
5. 对每条 ego 输出：

   `p_corrected = μ_R(c) + B · [p_ego − μ_E(c)]`

   这里 `B` 是作用于整条轨迹的矩阵。低秩部分取 6 维，协方差收缩为 0.3，传输特征值限制为 [0.25, 2]，其余方向保留 0.25 倍残差；这些值在揭示本轮误差前固定。姿态在 SO(3) 的局部旋转向量空间独立进行同类处理，再映回合法旋转矩阵。

与上一版选出的 `retain=0` 不同，主方法保留每条 ego 的残差。测试验证：在场景不变时修改某条 ego 的路径，输出也随之改变。均值重建 `scene_mean` 只作为预先声明的对照，不因其位置误差更小而改成主方法。

残差传输仍包含一个无法由无配对数据验证的假设：在共同场景/阶段坐标下，选择最小位移的高斯残差映射是合理的。它不是恢复了未知真实逐条对应关系，也不能保证保留的每个 ego 细节都是正确的。

## 参数怎么选择，如何隔离配对

场景回归的 ridge 从 `[0.01, 0.1, 1, 10, 100]` 中，通过**各自域内**的留一回归误差选择。目标是从该域自己的场景预测该域自己的轨迹，不是评价 ego 校正后是否匹配某条真机。特征标准化在各自域的已提供场景坐标上完成；留一误差使用固定设计矩阵的线性 smoother 公式。

流程分为独立命令：

1. `unpaired_redcube_prepare.py` 生成无身份信息的 `training.npz` 和只供评测使用的 `evaluation_private.npz`。
2. `unpaired_redcube_fit.py` 只能按接口读取六个训练数组。产生模型、全部预测及 SHA-256 封存清单；不读取 evaluator 文件。
3. **全部 5 轮模型和预测均封存后**，`unpaired_redcube_evaluate.py` 才读取配对真值。先核对封存哈希，再计算误差。
4. 应用／导出读取冻结模型及 ego 原始帧数据，重建出的阶段轨迹与封存预测一致。

另外，对每轮分别随机置乱 source 和 target 后重拟合，输出最大差异小于 `7e-15`，即浮点计算误差量级。这验证了实现不依赖两域行顺序对应。它与独立入口、输入字段检查一起提供审计证据；这不是操作系统级的访问隔离证明。

## 评测协议

参考真机按其自身 episode 排序后随机抽 20 条，种子预先固定为 20261011–20261015；主实验固定为 20261011。每轮独立使用 20 条真机和全部 100 条无标签 ego；没有合并五轮模型，也没有挑选最好一轮输出。5 轮用于量化参考数据选择的敏感性，不代表一个使用更多真机的模型。

配对表打开后，才能知道哪些 ego 的对应真机属于已提供的 20 条。主指标使用**对应真机未参与训练的 80 条 ego**；另外 20 条和全部 100 条的指标分开保存。100 条 ego 本身均参与无标签源域拟合，因此这是离线、transductive 校正，不是“从未见过测试 ego”的归纳学习。

位置指标为抓取/放置 TCP 的欧氏距离及阶段归一后的全路径均值；姿态为 SO(3) 测地角。长缺测区间的阶段点仍按固定规则遮罩。没有根据校正误差筛掉整条轨迹。配对图像存在初始位置差异的问题保持披露，位置一致子集只作为补充。

**这批数据上一轮已经被查看过，不能称为全新的盲测。** 本轮证据是严格无配对接口、封存预测和参考抽样敏感性；新的任务、相机与真正未使用数据仍需要后续独立验证。

## 实测结果

主实验 20261011，80 条对应真机未用于拟合的 ego；位置单位 cm，姿态单位 degree：

| 方法 | 抓取 | 放置 | 全路径 | 姿态 |
|---|---:|---:|---:|---:|
| 原始 ego | 11.54 | 13.46 | 13.85 | 19.92 |
| 无配对锚点均值偏移 | 2.08 | 1.47 | 3.58 | 17.11 |
| 场景均值偏移 + 完整 ego 残差 | 1.66 | 1.52 | 2.49 | 8.47 |
| 无配对条件均值重建 | 1.23 | 0.83 | 1.97 | 8.21 |
| 原 OT 内核，按本轮无配对协议重跑 | **1.25** | **1.01** | **2.17** | **7.05** |
| 新 SceneBridge，预先固定的主方法 | **1.30** | **1.03** | **2.19** | **7.33** |

**结论不是“新模型超过了原 OT”。** 新方法满足无配对约束、保留 ego 残差并有明显校正效果，但这次新的域内 ridge 选择和协方差处理并没有胜过原 OT 内核。主实验中，新方法相对原 OT 的抓取误差反而增加约 0.049 cm，配对 bootstrap 的差值区间支持这一小幅退步；完整比较见 `results.json`。不应以精度提升为由替换原 OT。

条件均值重建的位置误差更低，但丢弃 ego 的路径残差，且姿态误差更高。这里没有用配对测试分数选择残差保留系数、混合位置与姿态模型，或更换主方法。上一版有配对方案的 6.06° 不能在本轮无配对约束下直接作为已实现结果。

5 次独立 20 条真机抽样的主方法结果（每轮均评测其对应的 80 条；±为抽样间样本标准差，不是置信区间）：

| 指标 | 均值 ± 标准差 | 5 轮均值范围 |
|---|---:|---:|
| 抓取 | 1.310 ± 0.035 cm | 1.279–1.370 cm |
| 放置 | 1.035 ± 0.019 cm | 1.018–1.058 cm |
| 全路径 | 2.220 ± 0.026 cm | 2.186–2.257 cm |
| 姿态 | 7.365 ± 0.323° | 7.127–7.926° |

主实验中图像位置一致的 68 条测试子集：抓取 1.05 cm、放置 1.06 cm、全路径 2.07 cm、姿态 7.29°。全体 80 条仍是主结果。

相同方块初始位置不要求人和机器人具有完全相同的空中路线或事件延迟，因此这些是配对真机参考误差，不是物理任务成功率。对残差的保留与对单条真机路径的 MAE 之间也存在取舍。

## 代码、复现与输出

核心：`correction/unpaired_scene_bridge.py`。流程脚本：`scripts/unpaired_redcube_{prepare,fit,evaluate,artifacts}.py`。13 项新旧相关测试通过，包括不等规模数据、独立置乱、序列化与非零路径响应。

```bash
python -m scripts.unpaired_redcube_prepare \
  --dataset outputs/paired_redcube/dataset.json.gz \
  --out outputs/unpaired_redcube_20261011
# 对协议中五个 seed 分别训练；全部完成后才运行 evaluate
python -m scripts.unpaired_redcube_fit \
  --training outputs/unpaired_redcube_20261011/20261011/training.npz \
  --out outputs/unpaired_redcube_20261011/20261011
python -m scripts.unpaired_redcube_evaluate --root outputs/unpaired_redcube_20261011
python -m scripts.unpaired_redcube_artifacts --root outputs/unpaired_redcube_20261011
```

本地 `outputs/unpaired_redcube_20261011/` 保存协议、冻结代码哈希、5 轮模型/预测/评测、汇总及图表。服务器对应目录为：

```text
/mnt/data/xule/TATE/outputs/unpaired_redcube_20261011/
  corrected/unpaired_bridge/episode_XXXXXX/eef_corrected.json
```

交付的是预先指定的主实验 20261011 的全部 100 条输出，不是多轮集成。模型只使用该轮 20 条真机。保留原始时间轴、有效帧和夹爪状态，校正 TCP 与其相关姿态/速度字段；源文件及上一轮输出不覆盖。
